The Video URL node (`youtube-video`) is an app input: `INPUT_NODE_TYPES` and `INPUT_FIELD_MAP` carry it (`youtubeUrl`, `video-url`), so a published app, MCP `get_app_inputs` / `run_app`, the SDK's `apps.run` and a component input handle can take a video link. New: `videoLinkInputProblem` (the one rule for a link an app input accepts: a supported post link, or any other http(s) link the canvas node passes through), `isDirectVideoFileUrl` and `DIRECT_VIDEO_EXTENSIONS` (lifted from the server's URL validator), `MAX_VIDEO_LINK_INPUT_CHARS`, `VIDEO_LINK_DERIVED_FIELDS` and `dropStaleVideoLinkFields`. `mergeNodeInputOverrides` now drops what a Video URL node fetched for its previous link (the downloaded file and audio track, the title, the picture, the length) when an override points it at a new one. Additive. Also new: `isPrivateOrReservedIP` (moved from the server's fetch guard) and `isLocalOrPrivateHostname`, the literal-host rule (localhost, private and reserved addresses) the server's URL schema and the app runner's link card now share. Also new: `videoLinkRunNeeds` / `videoLinkNeedOf` (what a run must fetch for a Video URL node — the video, only its sound, or nothing — read by the editor, the app runner's card and the server), `VIDEO_LINK_AUDIO_CONSUMER_TYPES`, `AUTO_DOWNLOAD_MAX_SEC` and `YOUTUBE_MAX_HEIGHT`.
