The welcome popup can open again after a close without an answer. `balance().welcomeOffer` gains the optional `popupDue`: open the popup by itself now, decided by the server (the grant is unclaimed, "Maybe later" was never answered, and the popup has opened by itself fewer than three times, none of them in the last 24 hours). `popupSeen` stays, as `!popupDue`, for apps written before it; a server released before `popupDue` leaves it out, so read `popupDue ?? popupSeen === false`. `client.credits.markWelcomeOfferSeen(event?)` takes the new `WelcomeOfferSeenEvent`: `"shown"` when the popup opened by itself (counts one showing while the popup is due; a second within 24 hours, or one after "Maybe later" or the third showing, is not counted), `"later"` when the user answered "Maybe later" (it does not open by itself again). A close without an answer (the ×, Escape, a click outside) is reported by not calling it, and an app should not open the popup by itself twice in one visit. Called with no event it sends no body, which the server reads as `"later"`, so existing calls keep their meaning. To adopt: open the popup on `popupDue ?? popupSeen === false` instead of `!popupSeen`, call `markWelcomeOfferSeen("shown")` when it opens by itself and `markWelcomeOfferSeen("later")` on "Maybe later", and stop calling it on other closes.
