`wiredCharacterNames`: two wired Character nodes with the same typed name in a script the mention slug cannot spell (two "マヤ", two "מאיה", two "마야") are now one character, as two "Maya" nodes already were. The second node takes the first one's `character-N` key and uses no number of its own. Names compare after Unicode NFKC normalisation and case folding, with runs of punctuation and spaces read as one separator.

A name with a letter of another script is now keyed on that whole name, never on the Latin part the slug can spell. Before, different characters could merge: "マヤ1" and "レオ1" both went by `1`, and "マヤ A" went by `a`, the same as a character named "A". They are now different characters. Such a name keeps its own slug as its mention key while no other wired character claims that slug; otherwise it takes a `character-N` key, as a name the slug cannot spell does. A name whose letters are all Latin and that the slug can spell (accents included: "José" stays `jos`) is keyed by its slug exactly as before. An all-Latin name the slug cannot spell at all ("Ñ", "Ö") now follows the same-name rule as any name the slug cannot spell: two "Ñ" nodes are one character, while "Ñ" and "Ö" are two (before, every such node was a character of its own). New from `@nodaro/shared/entities`: `wiredCharacterSlug(names, nodeId, data)`, the slug a Character node goes by for the node it feeds ("" when it has none). `wiredCharacterKey` now reads it, so a node with a non-Latin name, wired only by its image pip, files its elements under the wired character with the same whole name, never under a character that shares only its Latin part. In the other direction, a Latin-named node wired only by its image pip ("A") is never filed under a wired character of another name that goes by its slug ("マヤ A", which is `a` while no other character claims it).
