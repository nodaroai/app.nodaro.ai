`client.apps.resume(slug, runId, { dryRun?, version? })` retries a failed app run from where it stopped: only the steps the run did not complete run and are charged, and every step it completed hands on its result. It runs the version the run ran, with the inputs the run applied. `{ dryRun: true }` returns what the Retry would run and charge (`AppRunResumePlan`: the steps, `estimatedCredits`, `reusedClips`, `sufficient`, `available`) and starts nothing; otherwise it returns the Retry's execution (`AppRunResumeResult`). Refusal codes are typed as `AppRunResumeRefusalCode`; a Retry refused because the app is on another version throws the new `AppRunVersionChangedError` (`@nodaro/sdk/errors`), carrying `runVersion` and `appVersion` — send `{ version: runVersion }` to continue on the run's own version, or start the run over with `apps.run`. A 409 `already_running` that names the execution under way (a top-level `executionId` — from `apps.resume` or `workflows.run`) now throws the new `AlreadyRunningError` (a `NodaroError`, same `code` and `status`) carrying that `executionId`, so the caller can follow it without another read; one that names a job is still a `ContinuationRefusedError`. `AppRunResumePlan.sufficient` covers the runner's app credits as well as the balance, and the plan carries `appCreditsAllowance` when the app credits are what stops the Retry.
