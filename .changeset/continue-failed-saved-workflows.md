A failed run of a saved workflow can be continued from where it stopped. `client.workflows.run` takes `continueMode: "from-failed"` with `continueFromExecutionId` (the run that failed); `nodeIds` is optional with it (default: every node), and the run executes only the nodes that run did not complete — what it completed is handed on, never run or charged again (per node: a node that failed runs again in full, every list item included). When a later continuation of that run completed only part of what it left, the run builds on the newest such one, and `RunWorkflowResult.continuedFrom` names the execution it continued from. `client.workflows.run` also takes a third argument, `{ idempotencyKey }`, sent as the `Idempotency-Key` header (a retry with the same key answers the run already started, `deduped: true` on the result). A run a later continuation supersedes is refused with `continuation_superseded`: one that failed is the one to continue, and one that completed everything the run left means the work is done. The CLI's `nodaro workflows run` takes `--continue-from <executionId>`, `--from-failed` and `--idempotency-key <key>`, and says when a continuation was built on a later one. A Render final, or a run of named nodes, that continues the newest later continuation joins the chain too. When the newest later continuation stopped at a Preview review — of a render, or of a Tighten Episode with review on — the run is refused with `continuation_preview_pending`: the answer names that run, what holds it, and the one run that finishes it (`next`, to send as the body of `client.workflows.run`; for a single render it is that run's Render final). The SDK throws it as the new `ContinuationPreviewPendingError` (`@nodaro/sdk/errors`: `executionId`, `renderNodeIds`, `reviewNodeIds`, and `next`, typed `HeldFinalRun`), so `client.workflows.run(workflowId, error.next)` finishes it. A Tighten Episode or Chapters node resumes its earlier failed attempt only when its inputs and settings are still the ones that attempt ran with; otherwise it runs fresh. `@nodaro/shared`: the `continuation_not_failed` and `continuation_superseded` codes now document the saved-workflow lane too, and the new `CONTINUATION_PREVIEW_PENDING` code joins `RUN_CONTINUATION_CODES`.
