New `wiredCharacterNames()` / `wiredCharacterNamesOf()` (with `characterOwnName()`, `wiredCharacterBySlug()`, `wiredCharacterKey()`, `aliasRetiredCharacterMentions()`, `CHARACTER_NODE_DEFAULT_LABEL`) and `entityImageUrl()`: what each Character node wired into one node is called, and the one image it sends. A node keeps the name it was given (its `characterName`, else a label someone typed); one still carrying the default label "Character Asset" is unnamed, and each unnamed node is its own character, "Character 1", "Character 2", … in wire order, skipping a number another wired character is already called. A typed name the mention slug cannot spell ("マヤ") is kept as typed and keyed `character-N` from the same sequence. A mention saved as `@character-asset:N` or `@character:N` reads as the only unnamed character wired in, and stays plain text when there are several. A character's portrait is the image its node outputs (`entityImageUrl`: the starred default asset, else the active result, else the source image). The editor's Run, the workflow run and the editor's panels all read these, so every path names the same characters the same way and sends one image for each.
