Typed image routes beside generate-image: `nodes.run` / `runAndWait` now have overloads for `image-to-image` (`ImageToImageParams`), `edit-image` (`EditImageParams` — either `imageUrl`, or `taskId` with one of the Grok task-op providers, never both), `generate-mask` (`GenerateMaskParams`; `runAndWait` resolves `GenerateMaskJobOutput`, the source `imageUrl` and its `maskUrl`) and `split-image` (`SplitImageParams` on `run` only — it is free and synchronous and answers `SplitImageResult`, the tiles as `{ name, url }[]`). The three job routes answer `ImageJobStarted`, so `result.jobId` is a `string` without a cast. `GenerateImageParams` also types the inpaint fields `baseImageUrl` and `maskUrl` (white = the area to change), plus `strength` and `guidanceScale`. The params take the platform's own vocabularies, re-exported from the SDK: `ModifyImageProvider`, `ImageEditProvider`, `TaskChainedEditProvider`, `ImageAspectRatio`, `ImageResolution`, `ImageQuality`, `ImageRenderingSpeed`, `ImageEditTargetResolution`, `TopazUpscaleFactor`, `ImageToImageAttachColumn`.

`@nodaro/shared` exports those lever vocabularies as tuples the routes' validation is now built from — `IMAGE_RESOLUTION_VALUES`, `IMAGE_QUALITY_VALUES`, `IMAGE_RENDERING_SPEED_VALUES`, `IMAGE_EDIT_TARGET_RESOLUTION_VALUES`, `IMAGE_TO_IMAGE_ATTACH_COLUMNS` — and `TASK_CHAINED_EDIT_PROVIDER_IDS` (with its type `TaskChainedEditProvider`), from which `TASK_CHAINED_EDIT_PROVIDERS` is now built. The values are the ones the routes already accepted, so nothing changes on the wire: an app that sent these bodies untyped keeps working (the generic `run(type: string, …)` overload is unchanged). The compile-time check applies to a body typed as the params type (`const params: EditImageParams = …`, or `{ … } satisfies EditImageParams`): a body written inline that the typed overload rejects still falls through to the untyped overload and resolves the untyped `RunNodeResult`, so use `satisfies` to get the check.
